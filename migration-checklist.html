เช็กลิสต์ย้ายระบบแชทโดยไม่ดาวน์ไทม์

การเปลี่ยนเครื่องมือจัดการแชทมักน่ากลัวกว่าความจริง — เช็กลิสต์นี้ทำให้ย้ายตอนกลางคืนได้โดยลูกค้าไม่รู้สึก

ก่อนย้าย 1 สัปดาห์

  • ส่งออกประวัติบทสนทนาทั้งหมด (CSV/JSON) พร้อม timestamp
  • ถ่ายรายการ quick reply, tag, และสิทธิ์ทีมทั้งหมดออกมาเป็นตารางเดียว
  • แจ้งลูกค้าผ่าน broadcast ครั้งเดียวว่ากำลังปรับปรุงระบบ (อย่าเงียบ)

คืนย้าย

  • ต่อช่องใหม่ก่อนปิดช่องเก่าเสมอ (run สองระบบพร้อมกัน 1–2 ชม.)
  • ให้ทีม 1 คนเฝ้าหน้าเก่ากันข้อความหลุด ระหว่างที่คนหลักทำงานหน้าใหม่
  • ทดสอบ 3 เคสจริง: ส่งข้อความเข้า → ตอบ → ตรวจสลิป → ปิดเคส

หลังย้าย 3 วัน

  • นับจำนวนบทสนทนาเข้า vs ส่งออก — ถ้าตัวเลขไม่ถึง 90% ของค่าเฉลี่ยเดิม มีช่องที่เชื่อมต่อหาย
  • ตรวจว่าเลขอ้างอิงการโอนยังค้นหาเจอ (สลิปเก่าห้ามหาย)

คำถามที่พบบ่อย

ย้ายแล้วเลขที่แชทเดิมจะเปลี่ยนไหม? — ระบบส่วนใหญ่ map ID เดิมไว้ ถ้าไม่ map ให้เก็บไฟล์ export ไว้เป็นหลักฐานอย่างน้อย 1 ปี
ต้องปิดร้านไหม? — ไม่ ถ้าทำนอกเวลาขายและ run สองระบบพร้อมกัน
ใช้เวลานานเท่าไหร่? — ตัวอย่างสมมติ: ร้านแชท 300 สนทนา/สัปดาห์ ใช้เวลาเตรียม 1 สัปดาห์ คืนย้ายจริง 2 ชม.
